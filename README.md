## Standards (evidence-first)
My standard approach favors automation and clarity. When configured in a repo, you’ll see:
- CI workflows under `.github/workflows`
- Packaging via `pyproject.toml` or `requirements.txt` / `setup.py`
- Security policy via `SECURITY.md` (when present)
- Tests under `tests/` (when present)
